# MyClicker — инструкции для агентов

Портативный автокликер для Windows: Python 3.12+, tkinter, ctypes, без сторонних библиотек во время работы. С пользователем общаемся по-русски.

## Документация — читать перед работой

- [`CONTEXT.md`](CONTEXT.md) — глоссарий. Код, тесты и ответы пишем его терминами (**Client**, **Target**, **Action**, **Profile**, **Input Method**, **Slot Fingerprint**, **Mini Panel**). Новый термин сначала добавляем туда.
- [`docs/adr/`](docs/adr/) — принятые решения. Перед изменением в затронутой области прочитай относящиеся к ней ADR. Новое решение, которое трудно отменить и которое без контекста выглядит странно, записываем следующим по номеру ADR.
- [`docs/research/lu4-input-methods.md`](docs/research/lu4-input-methods.md) — что работает и что не работает в LU4. Читай перед любой работой со способами ввода или пробами на игре; новые замеры дописывай туда и в `myclicker/domain/research.py`.

## Архитектура

- `myclicker/domain` — модель, расписание, движок, отпечатки, совместимость. Этот слой не импортирует Windows, его логика покрыта тестами.
- `myclicker/platform_win` — весь WinAPI. Каждый **Input Method** — отдельный класс, реализующий `MouseInputMethod` или `KeyboardInputMethod` из `myclicker/domain/input.py`. Новый способ ввода: класс → регистрация в `platform_win/registry.py` → статья в `ui/method_docs.py` → известные результаты в `domain/research.py`.
- `myclicker/app/controller.py` — единственная точка входа для интерфейса; `myclicker/ui` только отображает и вызывает контроллер.
- Всё, что программа записывает, лежит в `data/` рядом с программой (`myclicker/paths.py`): так папку можно переносить целиком.

## После каждого изменения

1. `python -m unittest discover -s tests -t .` — тесты зелёные. Новое поведение — сначала тест на одном из швов: `Engine`, `ProfileStore`, `FingerprintMatcher`, `CompatibilityTable`, `Controller`; Windows подменяется фейками из `tests/fakes.py`.
2. `python build.py` — пересобирает `MyClicker.exe` в корне репозитория. Он снова прогоняет тесты и без зелёных тестов не собирает.
3. Перезапусти программу (запущенные `run.py` / `MyClicker.exe`), чтобы пользователь видел текущую версию.
4. Коммит делаем по просьбе пользователя, и пересобранный `MyClicker.exe` всегда входит в него: exe в репозитории соответствует коду.

## Пробы на игре

Скрипты в `probe/` запускаются с правами администратора (игра работает от администратора). Результаты пишутся в `probe/results/` и в git не попадают: на скриншотах ники других игроков. Признак успеха игрового действия — новая строка в системном чате; чередуй её с макросом-разделителем, иначе одинаковые строки не различить (`probe/action_trials.py --separator`).

Скорость проверки Slot Fingerprint на живом клиенте меряет `probe/perf_fingerprint.py <профиль> [секунды]`: он только снимает окно и ничего не нажимает. Бюджет проверки держит `tests/test_fingerprint_perf.py`, подход описан в ADR 0002.

LU4 выполняет игровые действия от программного ввода только при недавнем живом вводе игрока — это защита от ботов. Работаем в её рамках: способы, которые подделывают присутствие человека, чтобы её обойти, в проект не добавляем.

## Подводные камни

- Файлы с кириллицей правь инструментами редактирования, а не `Get-Content`/`Set-Content` в PowerShell 5.1: они читают UTF-8 как ANSI и портят текст.
- `PrintWindow` нужен для снимков перекрытых окон игры; свёрнутое окно не снимается и кликов не принимает.
